# SF6 相性数据管线 —— 方法论

[English](METHOD.md) | **简体中文**

## 1. 数据来源

相性评分直接取自 [**Capcom 官方 Buckler API**](https://www.streetfighter.com/6/buckler/)：

    https://www.streetfighter.com/6/buckler/api/{lang}/stats/dia_master/{YYYYMM}
    https://www.streetfighter.com/6/buckler/api/{lang}/stats/usagerate_master/{YYYYMM}

这是公开的 JSON 接口 —— 无需浏览器、无需登录。（旧的 `stats/dia_master` *HTML*
页面对脚本会返回 403，但 `api/...` JSON 接口用普通浏览器请求头即可拿到同一份数据。）
每份 `dia_master` 数据按 control-total 口径给出大师及以上的对战相性图，覆盖
**36 / 40 / 41 / 42** 四个段位（大师 / 高阶大师 / 特级大师 / 究极大师），
每个段位是一张 30×30 矩阵：一个 30 项的 `opponent_header` 和 30 条 `records`，
每条记录的 `values` 数组给出对各对手的胜率（`val` 如 `5.237`，镜像对位为 `-`）。
单元格按 id 对齐（`_oid` → header 的 `id`），而非数组下标。`usagerate_master`
给出各段位每个角色的使用率。

每个相性评分是一个以 5.0 为中心的胜率刻度：`5.237` 表示所显示角色对该对手有
52.37% 的胜率。[Buckler](https://www.streetfighter.com/6/buckler/) 的优劣势分档：

| 评分 | 标签 |
|-------|-------|
| ≥ 5.3 | 有利 |
| ≥ 5.1 | 微有利 |
| ≥ 4.9 | 五五开 |
| ≥ 4.7 | 微不利 |
| < 4.7 | 不利 |

**为什么用官方 Buckler 而非镜像站？** 本项目最初镜像 kakuhanapp.com，但官方 API
在各方面都更优：它是数据的源头，使用 Capcom 的**官方英文名**（`M. BISON`、`AKUMA`、
`E. HONDA` 等），没有 DNS / 反爬的不稳定问题，存档可回溯至约 SF6 上线（202306）。
管线默认抓取 202502–202605（16 个月）；`matrix.csv` 与网页应用承载全部数据，
分析时可任选其中的子区间。

`download_buckler.py` 负责抓取并缓存原始 JSON；`build_matrix_buckler.py`
将其解析为长格式的 `matrix.csv`（schema 不变）以及 `usage.csv`。

> **操作类型（现代 / 经典）：** *全段位* 的 `dia` 接口额外按操作类型拆分角色，
> 但只给一个聚合的「Master」段位（无 MR 细分）。Capcom 不会把两个维度交叉 ——
> 你要么拿到技术段位（`dia_master`），要么拿到操作拆分（`dia`），二者不可兼得 ——
> 因此本管线采用技术段位数据，不建模现代 / 经典操作。

|------|-------------|
| `vega` | **M. BISON**（独裁者；日文「Vega」） |
| `gouki` | **AKUMA**（日文「Gouki」） |
| `honda` | E. HONDA |
| `cviper` | C. VIPER |
| `deejay` | DEE JAY |
| `aki` | A.K.I. |

slug 与旧镜像站保持一致，因此头像图（`web/img/{slug}.jpg`）仍能正常解析。

## 3. 段位与技术深度权重

[Buckler](https://www.streetfighter.com/6/buckler/) 提供四个段位的相性数据：
36（大师）、40（高阶大师）、41（特级大师）、42（究极大师）。管线支持全部四个段位，
按默认权重 **0 : 1 : 2 : 3**（大师 : 高阶 : 特级 : 究极）综合，
即 **大师默认排除、究极大师权重最高**。四个权重在网页应用中均可无级调节（段位权重滑块），
因此大师可随时被调回。

其依据是*技术深度*，而非样本量：段位越高，玩家对游戏的理解越深，其对局结果越接近
角色对角色的「真实」相性值，而非操作失误或对位认知不足所致。把究极大师权重设到最高，
因此偏向最具理解力的信号；大师（入门段位，人群最大但四段中技术最低）默认被排除出综合分
（权重 0），需要更广覆盖面时可用滑块调回。

这是一个**刻意偏向「偏差」的偏差 / 方差取舍**。这个取舍是实打实的，且与纯粹的方差最小化背道而驰：
究极大师人群最小、月度方差最高（经验上约为高阶大师的 2 倍），却被赋予最大权重 ——
恰与逆方差加权的做法相反。我们接受这份额外噪声，以追踪最高水平人群对每个对位的判断。
离散度标记（§6.3）会标出各段位分歧大到这份噪声值得警惕的对位。Buckler 不公开对局场次样本量，
因此无论如何都无法做真正的逆方差加权。

## 4. 平衡性时间线与月度存档

存档跨越 202502–202605（16 个月）。两个事件主导了所有权重决策：

- **2026-03-17**：全角色大型平衡补丁，与 ALEX 同步发布。这是最主要的版本分界线。
  202603 之前的每个月（202502–202602）都反映补丁前的环境；202604 起反映补丁后的环境。
  202603 是混合月：补丁在 3 月 17 日落地，因此该月约一半的对局历史在补丁前、一半在补丁后。

- **2026-05-27/28**：INGRID 发布，仅伴随一个小型系统补丁。INGRID 在 202605
  最多只有几天数据 —— 远不足以做稳定的相性估计 —— 故默认排除（`--exclude INGRID`）。

ALEX 随 3 月补丁发布，因此数据从 202603 起。INGRID 仅在 202605 有数据。

对于早于角色发布的（角色, 月份）组合，Buckler 返回 HTTP 500。下载器将持续的 HTTP
错误视为「无数据」事件并写入空标记文件，使重复运行保持幂等。在完整的 16 个月存档中
共有 136 个这样的空文件 —— 即 DLC 角色在其发布月之前、跨四个段位的空缺
（例如 INGRID、ALEX、C.VIPER、ELENA、SAGAT 各自上线前的若干月）。矩阵构建器会跳过它们
并逐一报告。

## 5. 月份权重方案

提供两个具名方案，外加完全自定义权重：

**`all`** —— 对每个请求月份等权（1.0）。这是「全窗口综合」视图；它包含补丁前环境，
适合在不强调补丁期的前提下观察整体的多月画面。

**`current`**（竞技向排名推荐）—— 补丁前的每个月权重为 0.0；补丁月（202603）为 0.5；
补丁后的每个月为 1.0。在完整的 16 个月存档中，这意味着 202502–202602（13 个月）全部归零 ——
丢弃补丁前数据是刻意为之，因为全角色大型平衡补丁会让旧对位不再能很好地代表当前环境。
该方案在偏重当前环境的同时，给过渡期的 3 月数据部分权重。若所有请求月份都落在补丁之前
（即所有权重都会是 0），方案会自动回退为等权，以避免得到空结果。

**自定义权重** —— `--weights 202601=0,202603=0.5,202604=1,202605=1` 会完全覆盖
具名方案。内部每个函数都接收一个普通的 `{月份: 权重}` 字典；这正是面向交互式网页前端的
重算 API：调节滑块 → 新字典 → 从 `matrix.csv` 重新计算，无需重新抓取任何数据。

分析表中的 **Δpatch（版本漂移）列**展示环境变化：某对手的特级大师补丁后均值减去
补丁前均值。Δpatch 为正表示补丁后该对位对本体变难了；为负表示变好了。

## 6. 评分聚合

对每个（角色, 对手）对，管线计算：

1. **逐段位月度均值**：对四个段位中的每一个，在请求月份上按当前权重方案做加权平均。
2. **段位综合分**：在有非空月度均值的段位上做 0:1:2:3 加权平均。若某段位在请求月份内
   无数据，则直接从分母中略去，而非按 0 计入；若某对手仅有的几个段位权重全为 0，
   则该对手被整体丢弃（没有可综合的加权数据）。
3. **离散度标记 ⚠**：当各可用段位评分之间的最大跨度超过 0.25 时给出，表明该对位评估
   在不同水平段之间存在显著分歧。
4. **月份覆盖**（如 `14/16`）：至少贡献一行评分的不同月份数，以请求总月份数为分母显示。
   存档中途上线的角色（ALEX 自 202603、INGRID 自 202605）分子会偏小；在整个请求区间
   都在场的角色显示满值（如整段存档下的 `16/16`）。

## 7. 反对称校验

在完美对称的数据集中，A 对 B + B 对 A = 10.0 恰好成立。然而 Buckler 的相性图是按
主角玩家人群分别统计的：A 对 B 的分来自 A 为「主角」（或更常用角色）的对局记录，
而 B 对 A 的分来自 B 为主角的另一份（虽有重叠的）人群。二者不是同一份样本，
因此两个数字不必恰好相加为 10.0。

`build_matrix.py` 将每个（月份, 段位, A, B）单元格与其对称对应项（月份, 段位, B, A）配对，
并计算每对相对 10.0 的绝对偏差。通过标准是**中位偏差 < 0.05**。在完整的 202502–202605
矩阵上的实际结果：**17,067 对，中位 0.0230，最大 0.3050**。最大值不是通过 / 失败标准，
仅作提示打印。偏差最大者集中在低人群角色（INGRID、LILY、A.K.I.）。偏差 > 0.2 的对会被
打印到控制台。

这里中位数才是恰当的稳健统计量：由于上述按人群的不对称，约五分之一的对会合理地超过 0.05，
因此用均值或最大值作标准会在干净数据上「失败」。注意该校验对*方向性*偏差是盲的 ——
因为每对都从两侧各计一次，带符号的偏差按构造相互抵消。它验证的是两侧*平均而言*一致，
而非任何单个角色的数字无偏。

## 8. 副角推荐

互补副角推荐按候选角色弥补本体最差对位的能力对其排序。

**补强分（COVER）**：

```
COVER = Σ w(O) · (副角对O − 5.0) / Σ w(O)
其中 w(O) = u(O) · usage(O) · sev(O) + max(0, u(O) − 1) · TARGET_INJECT
     sev(O) = max(0, 5.0 − 本体对O)²
     usage(O) = sqrt(play_rate(O) / 平均使用率)
```

`sev(O)` 是本体对对手 O 的弱点严重度：只有本体劣势（本体对O < 5.0）的对手才有正的严重度。
平方加权把注意力集中到最差的对位上 —— 对手在 4.0 的严重度是 1.0，而对手在 4.9 仅为 0.01。
COVER 为正意味着副角平均而言能赢下本体的麻烦对手；为负则意味着副角与本体共享、甚至加重了
这些弱点。

`u(O)` 是逐对手的**用户权重**（默认 1.0），在网页应用中以每个对手一个步进器呈现：

- **u = 1**（默认）精确复现纯弱点加权分 —— 注入项为 0，因此常规排名不受扭曲。
- **u = 0** 整体剔除该对手（例如 E.HONDA 或 DHALSIM 这类少有玩家具备有意义数据的低样本角色）。
  这就是「排除角色」的机制：零权重对手会从本体的弱点画像、每个副角的补强求和*以及*候选名单中
  一并移除。
- **u > 1** *针对*该对手。`max(0, u−1) · TARGET_INJECT` 项即使在 O 当前并非弱点（sev = 0）时
  也会加上权重，于是用户可以问「帮我找一个专克这个特定对位的副角」，无论本体是否已经占优。
  `TARGET_INJECT = 0.25` —— 即一个 4.5「微不利」对位的严重度 —— 因此针对操作总会把一个对手
  至少算作一个中等弱点，且这个量是固定的，与本体最差对位有多糟无关。

`usage(O)` 是一个**热度乘子**（默认开启；可在网页应用中切换），用于下调少有人玩的对手的权重。
它是 `sqrt(play_rate(O) / 平均)`，其中 `play_rate(O)` 是 Buckler 各段位使用率数据在
「段位 × 月份」网格上的**段位与月份加权**平均 —— `Σ W_r·w_m·u(O,r,m) / Σ W_r·w_m`，
使用与相性评分*同一套*段位权重 `W_r` 和月份权重 `w_m`。因此热度会随你设定的段位 / 月份焦点
变化：权重铺开时是大盘整体，权重集中时是你所在段位的当前环境。平均热度的对手 = 1.0，
热门者略高于 1，冷门者低于 1；`sqrt` 起到阻尼作用，使一个使用率 9% 的角色不会 9 倍碾压
使用率 1% 的角色。这缓解了冷门角色的虚高：副角「覆盖」一个几乎没人玩的对手，得分也更少。
关闭该开关时，所有对手 `usage(O) = 1`。

**专精度（SPEC）—— 强度调整后的补强**：

```
SPEC = Σ w(O) · (副角对O − 副角均值) / Σ w(O)
其中 副角均值 = 该副角综合相性行的均值（其整体「强度」）
```

COVER 有一个已知偏差：它奖励全局强势的角色。一个能赢*全表*的角色，按构造能覆盖*任何*本体的
弱点，因此 COVER 倾向于给几乎所有人推荐同样那几个顶级副角（JP、RASHID、DHALSIM）。一项跨全部
29 个本体的实证研究（[docs/findings-sub-bias.md](findings-sub-bias.md)）测得 COVER 与副角
原始强度的相关性约为 r ≈ +0.36。

SPEC 通过把每个副角的相性行以其自身均值为中心来消除该偏差：它问的是「相对于这个副角面对全表的
表现，它是否*专门*在你的弱点上超水平发挥？」一个一致强势的角色得分约为 0（它赢你的弱点并不比
赢别人更多）；一个真正的克制角色得分则高。SPEC 与原始强度的相关性约为 r ≈ +0.05（与强度无关），
且它**不会**推荐输家 —— 跨全部本体，它的头名赢下「最差三个」对位的频率与 COVER 不相上下。
副角表可按 COVER（默认）或 SPEC 排序，并以 **STR** 列显示每个副角的整体强度以便对照。注：
曾考察并否决了一个「冷门虚高」校正 —— 最常被推荐的副角并非一致地低方差（DHALSIM 是*极化度最高*
的角色），因此没有干净的特征能单独分离出「不熟悉对位」造成的虚高；若用户有此需求，逐对手排除
（u = 0）已能覆盖该情形。

**STR（强度）**：副角的整体平均相性分（即上文的「副角均值」），是一个段位代理。STR 高 =
对全表都强；将 STR 与 SPEC 搭配，可区分「这个副角只是单纯强」与「这个副角专门克我」。

**互补性列**：

- **corr**：本体与副角在共同对手上的完整相性分向量的皮尔逊相关系数。它衡量的是两条相性曲线的
  *形态*，**而非**补强：负值意味着副角与本体的胜负画像相反（副角倾向于在本体失利之处取胜），
  这正是用来凸显「最互补」角色的信号。由于皮尔逊相关系数对均值 / 尺度不变，一个全面*强于*本体
  但曲线形态相同的副角会显示为高度相关（看似「冗余」），尽管它其实是不错的选择 —— 因此 corr
  只是辅助的形态线索。真正的补强排名依据是 COVER，而非 corr。
- **shared**：两个角色都低于 4.9 的对手数量。共弱越少越好。
- **w3win%**：副角对本体最差三个对手（由 COMB 推出的最差 3）的平均胜率。以百分比显示（×10）。
- **COVER@HighM / COVER@GrandM / COVER@UltM**：仅用该段位的副角相性向量重算 COVER，
  而本体的弱点权重仍取自段位综合的 COMB 行。

## 9. 方法论细则

四个刻意为之且偏保守的已知边界情形：

**(a) 副角本身是本体最差 3 对手之一。** 若副角本身出现在本体的最差 3 中（例如 TERRY 的 JP），
那么副角对副角的镜像对位（JP 对 JP）在数据中不存在，会在 COVER 计算中中性填充为 5.0。这是刻意的：
5.0 是最中性的假设，避免抬高或压低得分。

**(b) 副角行中缺失的对手。** 若副角对某对手没有数据（最常见于只有三个月数据的 ALEX），
该对手在 COVER 分子中填充为 5.0。这会略微压低稀疏数据角色的 COVER，因为一个本该有利的对位
会被替换为中性，而绝不会被替换为有利分。

**(c) 逐段位 COVER 分歧。** COVER@段位 列只用该段位的副角相性向量。由于不同段位在个别对位分上
可能分歧，逐段位 COVER 值可能在*方向*上（而不仅是量级上）偏离全段位 COVER。这是信息，而非
一致性问题。

**(d) 最差 3 的推导。** 本体最差的三个对手取自段位综合的 COMB 行。一个仅在单一段位才构成实质
弱点的角色（例如在究极大师为 4.6 但在高阶大师为 5.1）在段位综合后可能不进入最差 3，因此最差 3
反映的是综合结果，而非任何单一段位的视角。

## 10. 个人模式 —— 收缩融合

网页应用的 **个人模式** 让每个视图都按你自己的战斗记录呈现，同时仍尊重全球数据。
对你当前的角色，它用一行 **收缩值** 替换全球综合（COMB）行 `m̄(O)`：每个对手的胜率
都是你的胜负数以全球基准作为 Beta-Binomial 共轭先验融合后的结果。

以基准胜率 `p0`（全球 COMB 分数 ÷ 10）为先验均值、先验强度 `κ = 20` 个伪对局，
你的 `w` 胜 `l` 负给出后验 `Beta(p0·κ + w, (1−p0)·κ + l)`；收缩胜率即其均值
`(p0·κ + w) / (κ + w + l)`，再 ×10 还原到以 5.0 为中心的刻度。两条性质让这种融合
可以安全地作为一个全局开关：

- **零对局 ⇒ 恰好等于基准。** 当 `w = l = 0` 时后验均值就是 `p0`，因此没有打过的对位
  与全球视图完全一致，在你没有数据的地方开关「开」与「关」完全重合。
- **证据逐步赢得信任。** 0–2 的战绩会被大幅拉回基准；30–20 的战绩则接近你观测到的
  60%。这与个人侦察报告使用的是同一个估计量（`scripts/bayes.py` / `web/scout.js`），
  因此判定阈值（真实弱点 / 超常发挥 / 样本不足 / 符合基准）与各个性化视图天然一致。

个性化的遭遇频率（个人模式下对位地图的横轴与副角推荐的使用率加权）来自你战斗记录的
原始计数，而非全球使用率表。候选副角的相性行仍使用全球数据 —— 你很少有自己不玩的
副角的对局数据。

## 11. 局限

- **没有样本量。** Buckler 不公开任何逐对位的对局场次。无法做样本量或逆方差加权；0:1:2:3 的段位
  权重是一个刻意的技术深度选择（§3），而非数据体量估计。
- **INGRID 数据极少。** INGRID 于 2026-05-27 发布。202605 的相性数据仅覆盖几天对局，极不稳定。
  INGRID 默认排除；重新纳入她（`--exclude` 不含 INGRID）应谨慎为之。
- **2026 年 3 月是混合月。** 2026-03-17 的补丁大致把该月一分为二。`current` 方案折中地赋予其
  0.5 权重；数据源无法提供月内的进一步分割。
- **究极大师噪声。** 究极大师人群最小、方差最高，0:1:2:3 方案却把它权重设到*最高*（§3）——
  这是刻意偏向最高水平人群、以更高方差为代价的取舍。究极大师的离群分会相应被放大；离散度警告
  （§6.3）会标出各段位分歧大到值得警惕的对位。
- **按人群的不对称。** 如第 7 节所述，A 对 B 与 B 对 A 的分取自不同玩家人群，不保证相加为 10.0。
  这是源数据的性质，而非管线的产物。
